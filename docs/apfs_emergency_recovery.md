# 现场 SSD 无法识别与 APFS 底层损坏急救指南

在影视影视现场 DIT 交付中，移动固态硬盘（SSD）因意外断电、不规范拔插或**固件硬件缺陷**，常会导致电脑提示：“磁盘无法装载”、“空间管理器无效（Space manager is invalid）”及 APFS 报错代码 -69845 / 退出代码 8。

本手册为现场急救的最高指导原则，旨在保护原始素材不被二次破坏，同时提供专业的数据挽救路线与客户沟通话术。

---

## 🚨 现场第一准则：绝对红线

### 1. 绝对严禁再次运行“磁盘工具 -> 急救 (First Aid)”！
当底层出现 `failed to read spaceman cib` 或 `Space manager is invalid` 报错时，说明 APFS 文件系统的空间管理器（记录磁盘可用/已用区段的账本元数据）发生了严重校验和损坏。
此时系统的 `fsck_apfs` 自动修复程序为了尝试填补空缺，可能会对损坏的元数据区**强行执行大面积覆写**，这会导致原本 intact（完好无损）的底层视频数据彻底撕裂或覆盖，让原本 100% 可恢复的数据永久丢失！

### 2. 绝对严禁随意“格式化后用软件恢复”！
对于 SSD 移动硬盘，格式化动作会在操作系统层触发 **TRIM 指令**。闪存主控会瞬间将整盘数据物理清空为 0。格式化后再去扫描，得到的结果只能是一片空白！

## 🛡️ 分级急救标准流程

### 阶段一：尝试终端强制只读挂载 (Read-Only Mount)
macOS 默认是以读写模式（Read-Write）挂载硬盘，一旦检测到文件系统脏标记或空间账本损坏，内核为了保护数据免受进一步破坏，会自动拒绝装载并弹窗报错。
我们可以通过 Mac 终端强行要求系统以“只读模式”忽略写入错误进行装载：

1. 打开 macOS **“终端 (Terminal)”** 应用。
2. 输入 `diskutil list` 回车，找到您故障固态硬盘对应的设备标识符（例如 `/dev/disk9s1`）。
3. 执行强制只读挂载命令：
   ```bash
   sudo diskutil mount readOnly /dev/disk9s1
   ```
   *(需要输入 Mac 电脑开机密码)*
4. **验证结果**：
   - **如果桌面成功出现硬盘图标**：请立刻拿出另一块格式健康的备用硬盘，**以最快速度把素材抢救拷贝出来**。
   - **如果终端提示挂载失败**：说明底层目录表树桩损坏过深，macOS 内核驱动已无法解析。请立即放弃系统工具，进入阶段二。

### 阶段二：底层第三方数据提取软件 (绕过 OS 挂载)
当操作系统无法挂载时，必须借助能够**直接读取硬盘底层原始区块（Raw Sector Blocks）**的专业工具。因为只有文件系统元数据坏了，99.9% 的大型 ProRes/RAW 视频文件本身在闪存颗粒上依然完好无损。

#### 推荐工具（现场建议首选 Disk Drill，简单高效）：
1. **Disk Drill (Mac)**：对 APFS 损坏结构的目录重建能力极强。
2. **UFS Explorer**：数据恢复行业顶级专业底层软件。
3. **R-Studio for Mac**：老牌工业级数据提取软件。

#### 操作流程：
1. 打开 Disk Drill，不需要等待系统认盘，它在“物理磁盘列表”中可以直接看到这块固态硬盘。
2. 选中故障 SSD，点击 **“搜索丢失的数据 (Search for lost data)”**。
3. 软件会深度解析残留的 B-Tree 结构。几分钟后，您会发现熟悉的摄像机文件夹结构悉数重现。
4. **将重要文件勾选后，点击“恢复 (Recover)”将数据直接另存（导出）至另一块全新的安全硬盘中**。

#### ⚠️ 硬件控温警告（极其关键）：
固态硬盘在发生主控卡死或逻辑死循环时，往往伴随严重异常发热。在 Disk Drill 漫长的导出过程中，**务必使用小型电风扇对着 SSD 全程吹风降温**，或将其放置于冷气出风口。避免高温引发主控彻底烧死断连！
